# 0004. Эмбеддинги в коротком отдельном процессе

**Статус:** принято

## Контекст

По плану модель эмбеддингов MiniLM должна была занимать около 150 МБ. Замер показал около 690 МБ на загрузке. Держать её в API или воркере постоянно на общем сервере нельзя.

## Решение

- `app/embed_worker.py` запускается воркером как отдельный процесс на время поиска и завершается; память освобождается.
- Эмбеддинги частых вопросов кэшируются в памяти воркера (до 128).
- Индекс — pgvector HNSW по cosine плюс русский FTS; результаты сливаются RRF. Ниже порога 0,38 модель не вызывается.

## Последствия

- Постоянное потребление памяти не растёт; первый поиск после простоя — на секунду-две дольше.
- Пересборка базы знаний (`scripts/build_kb.py`) идемпотентна по хешу текста, метаданных и модели.
