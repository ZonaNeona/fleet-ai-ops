# 0014. Маршрутизатор исполнителей агента: быстрый ответ → база знаний → Hermes → свой цикл

**Статус:** принято

## Контекст

У агента стенда один реестр инструментов (ADR 0008). Но не каждому вопросу нужна модель:
- «какие машины хуже всех» или «сколько нам должны» спрашивают постоянно, и ответ на них — это вызов одного
  инструмента;
- вопрос о правилах парка лучше отдавать базе знаний с проверенными цитатами;
- свободные составные вопросы — агенту. Заказчики спрашивают и про готовые агентные платформы — например,
  Hermes Agent.

## Решение

`agent.run` выбирает самый дешёвый исполнитель, который может ответить честно:

1. **Быстрый ответ** (`app/quick.py`):
   - узкие шаблоны намерений → инструменты под ролью задания → ответ собирается из их результата;
   - модель не вызывается, ответ стоит 0 и не тратит часовой лимит ИИ;
   - вопросы «почему», «что делать с…», «если…» и вопросы на две темы сразу идут дальше;
   - если роли инструмент недоступен, вопрос тоже уходит агенту.
2. **База знаний** — для вопросов о правилах: ответ по найденным фрагментам с цитатами.
3. **Hermes Agent** (профиль `fleet` на хосте), если он настроен и дневной бюджет позволяет:
   - Hermes ходит в инструменты стенда через его же MCP-сервер по HTTP с серверным ключом;
   - перед ходом стенд записывает ход (пространство, роль, время), и MCP-сервер выполняет вызовы Hermes в этом
     пространстве и под этой ролью — с теми же проверками, что у встроенного агента;
   - без активного хода инструменты не выполняются;
   - ходы идут по одному, стоимость записывается в учёт расходов на модели.
4. **Встроенный цикл с инструментами** — если Hermes не настроен, недоступен или не уложился во время.

Результат называет исполнителя; консоль «Агент» показывает его, стоимость и шаги.

### Сигналы «сделать сейчас»

`app/signals.py` — правила над данными пространства:
- долг без оплаты;
- аренда закончилась, договор открыт;
- просроченная заявка сервиса;
- кандидат завис в найме;
- «оплачено в CRM», а денег нет;
- звонок ниже нормы.

У каждого сигнала есть причина и следующее действие. Сигналы ничего не хранят: пересчитываются каждый раз
и исчезают, когда причина устранена. Они видны:
- на главной;
- в утренней сводке;
- в быстром ответе;
- в инструменте агента `get_signals` — доступен ролям, которые видят весь парк.

## Последствия

- Частые вопросы работают и тогда, когда модель недоступна или лимит исчерпан.
- Hermes — отдельный процесс на хосте (~300 МБ, ограничен systemd). Без него стенд отвечает встроенным циклом,
  разница видна в консоли.
- Шаблоны намерений узкие по замыслу: неясный вопрос лучше отдать модели, чем ответить не на то.
