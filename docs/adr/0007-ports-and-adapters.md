# 0007. Внешние системы — через порты, у каждой эмулятор и живой режим

**Статус:** принято

## Контекст

Стенд открыт всем и должен работать без чужих платных порталов. При этом подключение настоящего Битрикс24, 1С или платёжного провайдера должно быть настройкой, а не переписыванием. Бизнес-логика не должна знать, откуда пришли данные.

## Решение

- **Транспорт под общим портом.** У каждой внешней системы один порт и два транспорта.
  - Битрикс24 (`app/crm.py`): `Emulator` и `Live` с методом `call(method, params)` в формате REST портала.
  - Выше транспорта общий код для обоих: постраничное чтение, маппинг, воронки, сверка.
- **Эмулятор говорит на настоящем формате:**
  - числа строками;
  - `total` / `next` по 50 записей;
  - блок `time`;
  - коды стадий (`C1:NEW`).
  - Данные эмулятор строит из пространства посетителя, поэтому сделки ссылаются на настоящие договоры учёта.
- **Живой режим включается переменной окружения:**
  - `BITRIX24_WEBHOOK` — портал Битрикс24;
  - `ONEC_ODATA_URL` — 1С.
  - Живой адаптер пропускает только методы из закрытого списка. Запись — отдельное разрешение.
- **n8n.** Синтетические источники 1С, Яндекс Про, штрафов и телематики ходят через n8n теми же HTTP-узлами, что и для настоящих API.

## Последствия

- Стенд запускается из коробки (`docker compose up`), тесты идут без сети.
- Эмулятор обязан повторять формат API: иначе живой режим сломается незаметно. Поэтому формат проверяют тесты транспорта (`tests/test_crm.py`).
- Запись в чужую систему с публичного стенда закрыта на уровне адаптера.
