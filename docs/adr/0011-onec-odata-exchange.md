# 0011. Обмен с 1С по стандартному OData, идемпотентный ключ в комментарии

**Статус:** принято

## Контекст

Таксопарк ведёт бухгалтерию в 1С. Начисления аренды и оплаты водителей живут в учёте стенда, а акты и поступления
бухгалтер хочет видеть в 1С. Нужно:
- выгружать документы без двойного ввода и без дублей при повторном запуске;
- читать 1С обратно и находить то, что бухгалтер внёс руками;
- не требовать от заказчика доработки конфигурации 1С.

## Решение

- **Протокол — стандартный интерфейс OData 1С** (`/odata/standard.odata/<Набор>`), который включается публикацией
  базы без программирования. Чтение — `GET` с `$filter`, `$top`, `$skip`; запись — `POST` документа и `Post()` для
  проведения. Клиент (`app/onec.py`, класс `Live`) читает только из закрытого списка наборов, пишет только в два
  документа и только при `ONEC_WRITE=1`.
- **Выгрузка за прошлый месяц по договору:** начисления → «Реализация товаров и услуг», оплаты → «Поступление
  безналичных денежных средств». Ключ идемпотентности `FLEET:<договор>:<месяц>:<вид>` лежит в комментарии документа.
  Перед записью обмен читает документы месяца и пропускает уже существующие ключи — повтор ничего не задваивает,
  даже если между запусками база 1С восстанавливалась из копии.
- **Сверка в обе стороны:** документ есть в 1С, а в учёте нет; есть в учёте, а в 1С нет; суммы разошлись.
- **Эмулятор.** У каждого посетителя своя база 1С (`Item kind=onec_base`) с теми же наборами, `$filter` и записью.
  В неё заранее внесены две вещи, которые бухгалтер делает руками: выписка банка, загруженная только в 1С, и акт с
  опечаткой в сумме. Эмулятор доступен и по HTTP (`/api/onec/<ключ>/odata/standard.odata/…`) для n8n и curl;
  живая база наружу не проксируется никогда.

## Последствия

- Для подключения живой базы достаточно `ONEC_ODATA_URL`, `ONEC_USER`, `ONEC_PASSWORD` и прав пользователя 1С на
  нужные наборы.
- Комментарий как ключ — компромисс: его может стереть пользователь 1С. Для промышленного варианта ключ переезжает в
  дополнительный реквизит документа; меняется одна строка в клиенте.
- Workflow 1С в общем n8n по-прежнему читает снимок; перевод его на этот клиент требует переимпорта workflow
  и перезапуска n8n, который делит сервер с другими проектами, — сделаем в окно обслуживания.
