# 0005. Интеграции через n8n с подписанными пакетами

**Статус:** принято

## Контекст

Заказчики просят связать учёт с 1С, Яндекс Про, штрафами ГИБДД и телематикой, и часто — через n8n, чтобы потом менять потоки без программиста. При этом n8n — отдельный процесс со своей базой и редактором, а данные из него попадают в учёт, поэтому каждому пакету нужно доверять не больше, чем внешнему запросу.

## Решение

- Четыре workflow генерирует `n8n/build-workflows.mjs`: webhook / расписание → HTTP к источнику → Code-нормализация → подписанный пакет в API → ветка ошибки.
- Контекст запуска подписан HMAC и ограничен пространством, источником, запуском и десятью минутами. Источник подписывает нормализованное содержимое; подмена строк ломает проверку.
- Снимки источников хранятся отдельно от учёта; расхождения привязываются к машине. Деньги и пробег автоматически не меняются.
- Исполнения читает отдельный read-only адаптер (`scripts/n8n-reader.mjs`, loopback, HMAC), только по своим workflow.

## Последствия

- Секретов нет ни в workflow, ни в браузере.
- Источники пока синтетические; для настоящих систем нужны контракты API, учётные данные и правила сопоставления.
