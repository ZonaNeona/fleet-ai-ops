# Показ за 5 минут

1. **Лендинг.** Пять задач таксопарка и что из них уже работает. Кнопка «Открыть как собственник» создаёт личную демосессию: 160 машин, 90 дней истории.
2. **Дашборд собственника.** Выручка, результат после лизинга, страховки, ТО, ремонтов и общих расходов, загрузка и долги. Внизу — результат по каждой машине: откройте любую и посмотрите её экономику.
3. **Автопарк.** Переключите вид на карточки, выберите даты — календарь доступности учитывает брони и ремонт. Карточка машины: договоры, операции, история изменений, PDF и Excel.
4. **Заявки и сервис.** SRV-201 «Не запускается двигатель»: смета → согласование → ремонт → контрольный осмотр. Расход сразу попадает в экономику машины.
5. **Telegram-бот.** Раздел «Telegram-бот» в кабинете: эмулятор чата в рамке телефона работает на том же коде, что и настоящий бот, — Telegram для показа не нужен. Или откройте бота в Telegram.

# Сценарии в боте

* **Онбординг и ПДн:** «СТАРТ» → согласие на обработку персональных данных (152-ФЗ) → «Поделиться номером» → бот находит человека в учёте и открывает меню его роли. Номер хранится только хешем. Сотрудник входит по коду приглашения (демо: SERVICE-2026). /privacy — что хранится, /delete_me — отзыв согласия и удаление данных. Без согласия бот не выдаёт личные данные и не отправляет текст в модель.
* **Водитель:** «Штрафы ГИБДД» — запрос идёт через n8n-интеграцию, по машине водителя приходит учебное постановление.
* **Водитель:** баланс и долг, своя машина с фото, «Выходной завтра» уходит финансистам, свободный вопрос — ответ агента по своим данным; описание поломки — черновик с кнопкой подтверждения; фото — заявка в сервис, договор PDF.
* **Клиент проката:** «Подобрать автомобиль» → inline-календарь дат → серверный расчёт → резерв. Или «Кабинет клиента» → каталог, карточка автомобиля и бронирование внутри Mini App.
* **Сотрудники:** бот показывает «В демо доступно в веб-кабинете». Там менеджер подтверждает бронь, сервис ведёт ремонт, финансист согласует деньги. Собственник открывает мобильный дашборд.
* Кнопка «Кабинет клиента» или «Кабинет водителя» открывает отдельный мобильный интерфейс. В эмуляторе приложение выезжает прямо внутри телефона, в той же демосессии.

# Mini App: замкнутый сценарий

1. На лендинге выберите «Бот и кабинет клиента». В телефоне: «СТАРТ» → согласие → демороль клиента → «Кабинет клиента».
2. Выберите автомобиль и срок 7 дней: сервер покажет скидку 5%, услуги и отдельный возвратный залог. «Забронировать» создаст резерв на 30 минут; бронь появится в «Мои аренды».
3. Переключите демонстрационную роль на менеджера в шапке веб-приложения. Mini App закроется; в разделе договоров найдите новую бронь и подтвердите её. Если загружали новые документы, сначала выполните их проверку в роли специалиста проверки.
4. Вернитесь в роль клиента и откройте ту же аренду: оплатите учебный залог. Реального списания нет. Доступна PDF-квитанция, финансист видит ровно одну операцию. При выдаче второй залог не создаётся.
5. В кабинете водителя: долг и ближайшие начисления, учебная оплата, штрафы через n8n, мастер ДТП с адресом и фотографиями, предсменный осмотр с четырьмя ракурсами. Замечание осмотра появляется в очереди сервиса.

Подробности: docs/MINIAPP.md.

# Как это устроено

* Бот и веб вызывают одни и те же бизнес-команды: роль, принадлежность объекта, допустимый статус, ключ идемпотентности, аудит — в одной транзакции.
* Вебхук Telegram проверяет `secret_token`, отсекает повторы по `update_id` и ставит задачу в очередь; воркер отвечает асинхронно.
* Брони не пересекаются на уровне PostgreSQL (`EXCLUDE` по временным диапазонам).
* Деньги — точные десятичные суммы; исправления только сторно; залог не считается выручкой.
* Общие расходы распределяются по доступным автомобиледням, поэтому сумма по машинам сходится с итогом.

# Ограничения демо

* Данные учебные: модели автомобилей настоящие, суточные ставки и расходы (лизинг, страховка, ремонт) — условные.
* Каждый гость получает своё пространство; роль можно переключать — это режим показа, а не авторизация сотрудников.
* Внешние учётные системы не подключены: банковская выписка импортируется из файла, остальные источники обозначены как тестовые.

## «Под капотом»: ещё 5 минут

Переключатель «Продукт ⇄ Под капотом» в шапке меняет весь контур: вместо кабинета открывается инженерная консоль — тёмная, со своей навигацией. Каждый раздел — живой холст: узлы, связи с бегущими импульсами, камера следует за активным шагом, справа — инспектор, снизу — таймлайн с реальной длительностью шагов. Уровень объяснения — «Просто» или «Инженер» (вверху справа). Прямая ссылка: https://fleet.shvarev-demo.ru/#under/map

1. **Карта системы.** Выберите сценарий над схемой: «Водитель спрашивает долг в боте», «Вопрос по регламенту», «Клиент бронирует автомобиль», «Синхронизация с 1С». Запрос проходит через вебхук, очередь, воркер, агента, проверку прав и PostgreSQL; каждый шаг подписан. Клик по узлу — что он делает.
2. **RAG.** Спросите «Какие документы нужны водителю?». Конвейер проигрывается по настоящей трассе: смысловой отпечаток (384 числа), поиск по смыслу и по словам, слияние RRF с порогом, контекст, модель, проверка ссылок. Клик по узлу — его данные: найденные фрагменты с оценками, промпт, модель и стоимость. «Как приготовить борщ?» — система честно отказывается, модель не вызывается.
3. **Агент.** Модель в центре, шесть инструментов справа. Инструменты, недоступные роли, под замком. Спросите «Сколько я должен?», затем смените роль вверху на менеджера — замки и ответ изменятся. «Стучит подвеска…» создаёт только черновик; заявку создаёт человек кнопкой «Подтвердить».
4. **Интеграции.** Настоящий workflow n8n для 1С, Яндекс Про, штрафов и телематики. «Запустить workflow» — исполнение проигрывается по нодам; справа — строки, расхождения (клик открывает автомобиль в продукте), история запусков. В режиме «Инженер» видны код Code-нод и пример данных.
5. **Журнал.** Живая лента: AI-задания, вебхуки, синхронизации, аудит. Выберите событие — трасса и кнопка «Проиграть на холсте».

В новом пространстве источники ещё не запускались. После ручного запуска источник включается в почасовое расписание для активной демосессии. Действующие сессии сохраняют свои данные; новые учебные даты начала ремонта появляются в новых пространствах.
