# Контур «Под капотом»

Контур открывается переключателем «Продукт ⇄ Под капотом» в шапке и по адресу https://fleet.shvarev-demo.ru/#under/<раздел> (map, rag, agent, n8n, log). Это отдельная оболочка — инженерная консоль со своей навигацией, а не вкладка меню. Каждый механизм показан на холсте (React Flow, свои узлы, частицы по связям, камера следует за активным шагом), справа — инспектор шага, снизу — таймлайн. Уровни объяснения «Просто» / «Инженер». Анимация воспроизводит сохранённое исполнение; длительности, результаты и стоимость — из настоящих вызовов. Фронтенд: `web/under/` (`UnderShell`, `flow.tsx`, `SystemMap`, `RagView`, `AgentView`, `N8nView`, `LogView`).

## RAG

Корпус: 20 документов, 31 фрагмент. Публичные источники отделены от учебных регламентов, у каждого есть версия. Общая база содержит только публичные и специально подготовленные учебные тексты; файлы посетителей туда не попадают.

Локальная модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` создаёт 384-мерные векторы. Поиск соединяет cosine pgvector/HNSW и русский PostgreSQL FTS/GIN через RRF. Порог cosine — 0.38, контекст — до пяти фрагментов. При отсутствии результата LLM не вызывается. Ссылки ответа проверяются на принадлежность найденным фрагментам. Это проверка ссылок, а не доказательство фактической правильности всего текста.

В исходном плане оценка памяти модели была 150 МБ. Замер показал около 690 МБ на загрузке. Поэтому `app/embed_worker.py` запускается отдельным короткоживущим процессом из единственного worker; после поиска память освобождается. Основные API/worker не держат модель постоянно. Эмбеддинги вопросов кэшируются в памяти worker, максимум 128 вопросов. Модель берётся из существующего общего кеша `/tmp/fastembed_cache` с правом чтения для пользователя `fleet`. Чужой AI-сервис не вызывается. После очистки `/tmp` модель нужно восстановить до запуска RAG.

```bash
cd /var/www/fleet
PYTHONPATH=. .venv/bin/python scripts/build_kb.py
PYTHONPATH=. .venv/bin/python scripts/check_rag.py
```

Пересборка идемпотентна по хешу текста, метаданных и модели; выполняется под advisory lock.

## Агент и Telegram

Шесть инструментов: get_balance, list_vehicles, vehicle_economics, find_contract, search_knowledge, create_ticket. Список разрешённых инструментов зависит от роли. Каждый вызов повторно проверяет роль и видимость объектов; запись Job фиксирует роль на момент постановки задания. Максимум четыре шага модели и четыре инструмента за шаг.

create_ticket сохраняет черновик на 10 минут. Подтверждение проверяет пространство, роль, срок и актуальную доступность автомобиля, затем вызывает обычную бизнес-команду. Повторное подтверждение возвращает прежний результат. Инструментов списания денег, изменения договоров и согласования сметы у модели нет.

Свободные сообщения в Telegram и режим «Агент» веб-помощника используют одну реализацию. Конкретная неисправность приводит к предложению черновика; общий вопрос о правилах — к поиску. Фотографии и явный ручной сценарий заявки сохраняют прежнее поведение. В журнал пишется факт обработки вебхука без текста сообщения и Telegram ID.

Модель идёт через существующую разрешённую цепочку провайдеров, первой — DeepSeek, резерв — настроенный OpenRouter-совместимый шлюз. Каждый реальный вызов резервирует стоимость в общем бюджете $0.50 за сутки МСК. На пространство — 10 AI-заданий в час. При недоступности модели показывается ошибка; подготовленные ответы не подставляются. Неоднозначные платные запросы автоматически не повторяются.

## Интеграции

Четыре активных процесса собственного n8n стенда (`/var/www/fleet-n8n`, pm2 `fleet-n8n`, ставится `scripts/setup_n8n.sh`): `<prefix>-1c`, `<prefix>-yandex-pro`, `<prefix>-fines`, `<prefix>-telematics` (префикс — `N8N_PREFIX`, по умолчанию `fleet`). Реальные webhook/HTTP/Code-узлы получают учебный снимок пространства, нормализуют поля и отправляют подписанный пакет в API. Ветка ошибки записывает неуспешное исполнение. Генератор и экспорт — в `n8n/`.

1С использует учебный OData-подобный снимок справочника автомобилей и начислений. Это не реализация полного протокола OData и не соединение с настоящей 1С. Яндекс Про, штрафы и телематика также синтетические. Фиксированные расхождения нужны для воспроизводимого показа; они не означают реальные штрафы или движение автомобилей.

Снимки источников хранятся отдельно от своего учёта. Расхождения привязываются к автомобилю. Повторная загрузка обновляет записи по ключу источника/автомобиля; повторный ingest одного запуска возвращает прежний результат. Финансовые проводки и пробег автоматически не изменяются. Для настоящих систем следующим этапом нужны контракты API, отдельные учётные данные, правила сопоставления и разрешения расхождений.

Контекст подписан HMAC и ограничен пространством, источником, запуском и десятиминутным сроком. Мок подписывает нормализованное содержимое до передачи в n8n; изменение строк ломает проверку. Секрет отсутствует в экспортированных workflow и в браузере. `/api/mock/` закрыт nginx снаружи; внутренние маршруты дополнительно проверяют loopback и подпись.

Ручной запуск включает выбранный источник в почасовое расписание для активной демосессии. Schedule срабатывает на седьмой минуте часа, выбирает до пяти активных пространств без свежего запуска. Новым посетителям фоновые интеграции без первого ручного запуска не включаются.

Исполнения читает отдельный read-only reader: `scripts/n8n-reader.mjs`, только `127.0.0.1:3014`, запросы с короткой HMAC-подписью. Он читает SQLite n8n без записи и возвращает только четыре разрешённых workflow, найденные по случайному ID запуска. Примеры строк фильтруются по пространству; подписи и секреты наружу не выдаются. Права других приложений и их workflow не расширялись.

## Размещение и откат

Фронтенд собирается локально (`npm run build`: tsc + esbuild); на сервер едет готовый `dist/`. API слушает loopback:3008. PM2 управляет `fleet-api`, `fleet-worker` и маленьким read-only адаптером `fleet-n8n-reader`. Общий n8n — отдельный существующий сервис, его перезапуск при обычном релизе не нужен.

Выкладка одной командой: локально `bash scripts/pack.sh`, на сервере `bash scripts/deploy.sh /tmp/fleet-release.tar.gz` (`--kb` — пересобрать базу знаний). Скрипт снимает бэкап и снимок релиза, сохраняет старые чанки фронтенда для открытых вкладок, применяет миграции, перезапускает процессы и проверяет `/api/health`.

Секрет интеграций — `/etc/fleet-integrations.env` (root:fleet 0640): `INTEGRATION_SECRET`, `N8N_HOME`, `N8N_PREFIX`, `N8N_SCHEDULER_HEADER`. Учётные данные расписания для импорта в n8n готовит `scripts/setup_integrations.py` в `/var/lib/fleet/n8n-credentials.json` (root 0600, вне репозитория).

Откат приложения: вернуть `app/` и `dist/` из каталога в `LAST_RELEASE`, перезапустить `fleet-api fleet-worker`, проверить health. Пользовательскую БД не откатывать поверх новых данных; миграции добавочные. Если отключается весь контур интеграций — деактивировать только четыре своих workflow, остальные процессы n8n не трогать.


Прогон бота использует настоящую бизнес-логику, БД и модель, но перехватывает исходящие сообщения: не отправляет ничего синтетическому Telegram ID. Проверка Telegram webhook и Mini App подписей покрыта интеграционными тестами; этот прогон сам по себе не проверяет доставку сообщения через сеть Telegram. Результаты — в `reports/` на сервере.
