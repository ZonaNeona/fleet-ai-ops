# Контур «Под капотом»

Контур открывается переключателем «Продукт ⇄ Под капотом» в шапке и по адресу https://fleet.shvarev-demo.ru/#under/<раздел> (map, rag, agent, docs, n8n, robot, mcp, ops, log). Это отдельная оболочка — инженерная консоль со своей навигацией, а не вкладка меню. Каждый механизм показан на холсте (React Flow, свои узлы, частицы по связям, камера следует за активным шагом), справа — инспектор шага, снизу — таймлайн. Уровни объяснения «Просто» / «Инженер». Анимация воспроизводит сохранённое исполнение; длительности, результаты и стоимость — из настоящих вызовов. Фронтенд: `web/under/` — оболочка `UnderShell`, холст `flow.tsx`, общие части `kit.tsx` и по экрану на раздел (`SystemMap`, `RagView`, `AgentView`, `DocsView`, `N8nView`, `RobotView`, `McpView`, `OpsView`, `LogView`).

## RAG

Корпус: 20 документов, 30 фрагментов. Публичные источники отделены от учебных регламентов, у каждого есть версия. Общая база содержит только публичные и специально подготовленные учебные тексты; файлы посетителей туда не попадают.

Локальная модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` создаёт 384-мерные векторы. Поиск соединяет cosine pgvector/HNSW и русский PostgreSQL FTS/GIN через RRF. Порог cosine — 0.38, контекст — до пяти фрагментов. При отсутствии результата LLM не вызывается. Ссылки ответа проверяются на принадлежность найденным фрагментам. Это проверка ссылок, а не доказательство фактической правильности всего текста.

При загрузке модель занимает около 690 МБ, поэтому `app/embed_worker.py` запускается коротким отдельным процессом из воркера; после поиска память освобождается, API и воркер модель постоянно не держат (ADR 0004). Эмбеддинги вопросов кэшируются в памяти воркера, до 128 вопросов. Модель читается из локального кеша (`FASTEMBED_CACHE_PATH`); внешний сервис эмбеддингов не нужен.

```bash
cd /var/www/fleet
PYTHONPATH=. .venv/bin/python scripts/build_kb.py
PYTHONPATH=. .venv/bin/python scripts/check_rag.py
```

Пересборка идемпотентна по хешу текста, метаданных и модели; выполняется под advisory lock.

## Агент и Telegram

Девять инструментов: `get_balance`, `list_vehicles`, `vehicle_economics`, `find_contract`, `search_knowledge`, `create_ticket`, `crm_pipeline`, `crm_task`, `get_signals`. Реестр один (`app/agent.py`): его же отдают MCP-сервер и Hermes Agent. Список разрешённых инструментов зависит от роли. Каждый вызов повторно проверяет роль и видимость объектов; запись Job фиксирует роль на момент постановки задания. Максимум четыре шага модели и четыре инструмента за шаг.

Маршрутизатор исполнителей (ADR 0014): частые вопросы собственника отвечаются инструментами без модели (`app/quick.py`, стоимость $0); вопрос о правилах идёт в базу знаний; остальное — Hermes Agent по HTTP, который вызывает инструменты стенда через MCP в пространстве и роли текущего хода (`app/hermes.py`). Если Hermes недоступен, отвечает встроенный цикл. В трассе видно, кто ответил.

`create_ticket` и `crm_task` сохраняют черновик на 10 минут. Подтверждение проверяет пространство, роль, срок и актуальную доступность автомобиля, затем вызывает обычную бизнес-команду. Повторное подтверждение возвращает прежний результат. Инструментов списания денег, изменения договоров и согласования сметы у модели нет.

Свободные сообщения в Telegram и режим «Агент» веб-помощника используют одну реализацию. Конкретная неисправность приводит к предложению черновика; общий вопрос о правилах — к поиску. Фотографии и явная кнопка заявки идут обычным сценарием бота. В журнал пишется факт обработки вебхука без текста сообщения и Telegram ID.

Цепочка провайдеров (`app/ai.py`): DeepSeek напрямую, если задан ключ, затем модели OpenRouter; при лимитах, сбоях и таймаутах берётся следующая. Каждый реальный вызов резервирует стоимость в общем бюджете $0.50 за сутки МСК. На пространство — 10 AI-заданий в час. При недоступности модели показывается ошибка; подготовленные ответы не подставляются. Неоднозначные платные запросы автоматически не повторяются.

## Интеграции

Четыре активных процесса собственного n8n стенда (`/var/www/fleet-n8n`, pm2 `fleet-n8n`, ставится `scripts/setup_n8n.sh`): `<prefix>-1c`, `<prefix>-yandex-pro`, `<prefix>-fines`, `<prefix>-telematics` (префикс — `N8N_PREFIX`, по умолчанию `fleet`). Реальные webhook/HTTP/Code-узлы получают учебный снимок пространства, нормализуют поля и отправляют подписанный пакет в API. Ветка ошибки записывает неуспешное исполнение. Генератор и экспорт — в `n8n/`.

Процесс 1С в n8n читает снимок справочника автомобилей и начислений в формате OData. Двусторонний обмен с 1С — отдельный модуль `app/onec.py` со своим эмулятором протокола (ADR 0011). Яндекс Про, штрафы и телематика синтетические. Фиксированные расхождения нужны для воспроизводимого показа; они не означают реальные штрафы или движение автомобилей.

Снимки источников хранятся отдельно от своего учёта. Расхождения привязываются к автомобилю. Повторная загрузка обновляет записи по ключу источника/автомобиля; повторный ingest одного запуска возвращает прежний результат. Финансовые проводки и пробег автоматически не изменяются. Для настоящих систем нужны контракты API, отдельные учётные данные, правила сопоставления и разрешения расхождений.

Контекст подписан HMAC и ограничен пространством, источником, запуском и десятиминутным сроком. Мок подписывает нормализованное содержимое до передачи в n8n; изменение строк ломает проверку. Секрет отсутствует в экспортированных workflow и в браузере. `/api/mock/` закрыт nginx снаружи; внутренние маршруты дополнительно проверяют loopback и подпись.

Ручной запуск включает выбранный источник в почасовое расписание для активной демосессии. Schedule срабатывает на седьмой минуте часа, выбирает до пяти активных пространств без свежего запуска. Новым посетителям фоновые интеграции без первого ручного запуска не включаются.

Исполнения читает отдельный read-only reader: `scripts/n8n-reader.mjs`, только `127.0.0.1:3014`, запросы с короткой HMAC-подписью. Он читает SQLite n8n без записи и возвращает только четыре разрешённых workflow, найденные по случайному ID запуска. Примеры строк фильтруются по пространству; подписи и секреты наружу не выдаются.

## Размещение и откат

Фронтенд собирается локально (`npm run build`: tsc + esbuild); на сервер едет готовый `dist/`. API слушает loopback:3008. pm2 управляет `fleet-api`, `fleet-worker`, `fleet-n8n` и read-only адаптером `fleet-n8n-reader`; systemd — `fleet-hermes` и Redis; приложение Битрикс24 работает в своём пуле PHP-FPM. Обычный релиз перезапускает только API и воркер.

Выкладка одной командой: локально `bash scripts/pack.sh`, на сервере `bash scripts/deploy.sh /tmp/fleet-release.tar.gz` (`--kb` — пересобрать базу знаний, `--quality` — замерить качество кода). Скрипт снимает бэкап и снимок релиза, сохраняет старые чанки фронтенда для открытых вкладок, применяет миграции, перезапускает процессы и проверяет `/api/health`.

Секрет интеграций — `/etc/fleet-integrations.env` (root:fleet 0640): `INTEGRATION_SECRET`, `N8N_HOME`, `N8N_PREFIX`, `N8N_SCHEDULER_HEADER`. Учётные данные расписания для импорта в n8n готовит `scripts/setup_integrations.py` в `/var/lib/fleet/n8n-credentials.json` (root 0600, вне репозитория).

Откат приложения: вернуть `app/` и `dist/` из каталога в `LAST_RELEASE`, перезапустить `fleet-api fleet-worker`, проверить health. Пользовательскую БД не откатывать поверх новых данных; миграции добавочные. Чтобы отключить контур интеграций, достаточно деактивировать четыре workflow стенда.

Проверка Telegram webhook и Mini App подписей покрыта интеграционными тестами; этот прогон сам по себе не проверяет доставку сообщения через сеть Telegram. Результаты — в `reports/` на сервере.
