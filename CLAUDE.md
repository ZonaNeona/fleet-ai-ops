# CLAUDE.md — правила проекта для ИИ-агентов

Стенд «Таксопарк»: учёт автопарка + ИИ-слой. Код пишется с ИИ-агентами (Claude Code, Cursor, Codex); за результат отвечает человек. Эти правила читает агент перед любой правкой.

## Стек и запуск
- Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL 16 + pgvector, Alembic; воркер — очередь заданий в PostgreSQL (`app/worker.py`).
- React 19 + TypeScript, Tailwind, React Flow; сборка `npm run build` (tsc + esbuild).
- Локально целиком: `docker compose up --build` → http://localhost:8080 (интеграции в режиме эмуляторов).

## Как устроено
- Все изменения данных — через `app/domain.py::command` (роль, статус, версия, ключ идемпотентности, аудит в одной транзакции). Не писать в `items`/`entries` в обход, кроме сидов.
- Инструменты агента — один реестр в `app/agent.py`; MCP и бот берут его же (ADR 0008).
- Внешние системы — через транспорт с эмулятором и живым режимом (ADR 0007). Эмулятор повторяет настоящий формат API.
- Тяжёлое (эмбеддинги, граф документов) — короткими подпроцессами: сервер 4 ГБ на несколько проектов (ADR 0004, 0006).
- ИИ — только через `app/ai.py` (бюджет, стоимость в трассе). Ответы модели не подменяются заготовками.

## Правила
- Данные учебные. Никаких имён и данных реальных компаний: `python tools/check_private_names.py` должен проходить.
- Секреты только в `/etc/fleet*.env` на сервере или `.env` локально; в коде и логах их нет.
- Перед коммитом: `ruff check` и `ruff format` (app scripts tests tools migrations), `mypy`, `npm run format:check`, `npm run build`; тесты — `pytest` на PostgreSQL (CI или `docker compose`).
- Новый модуль = тест + строка в README + при необходимости ADR. Комментарии — «почему», а не «что».
- Интерфейс по-русски, код и комментарии в коде — по-английски, тексты для людей — без канцелярита.

## Выкладка
`bash scripts/pack.sh` → архив → `bash scripts/deploy.sh /tmp/fleet-release.tar.gz [--kb] [--quality]`: бэкап, снимок релиза, миграции, рестарт, health, замер качества.
